# 0002. プロジェクト詳細の入力方式を「ファイル記入+グローバル`/init`」に統一する

## ステータス

採用

## コンテキスト

[Issue #1](https://github.com/qack-dev/my-claude-code-harness-project/issues/1) にて、以下の指摘があった。

- 現状の仕様が「Claude Codeとの対話でプロジェクト詳細を詰め始める」のか「ファイルに書き込んでから起動する」のか、リポジトリ内の記述だけでは判断できない
- `templates/questions.json` の `usage_note` や `docs/PRD.md` / `docs/ARCHITECTURE.md` は「AIエージェントが質問を尋ねる」という対話前提の書き方をしている一方、`README.md` の「使い方」は「回答を用意する」としか書いておらず、両者の対応が取れていなかった

対話ベースのままだと、AIエージェントとの1問1答が毎回発生し、新規プロジェクトを頻繁に立ち上げる本プロジェクトの想定ユーザー(`qack-dev`)にとって手間になる。一方で、質問への回答を機械的にすべて事前入力させる方式にすると、`[要確認: 内容]` のように人間の判断が必要な項目まで無理に埋めさせることになりかねない。

また、当初案では「新規プロジェクトを作るたびに `.claude/commands/init.md` をコピーする」という手順を含めていたが、これはプロジェクトを立ち上げるたびに手作業が発生し、ハーネス導入の手間を減らすという本プロジェクトの目的と矛盾するという指摘を受けた。Claude Codeはプロジェクト単位の `.claude/commands/` に加えて、ユーザースコープ(ホームディレクトリ配下)のグローバルコマンドにも対応している。

## 決定

- プロジェクト詳細の一次情報源は、新規プロジェクトのルートに置く `PROJECT_BRIEF.md`(`templates/PROJECT_BRIEF.md.template` から生成)とする。ユーザーはAIと対話する前に、分かる範囲でこのファイルを手で記入する
- `templates/commands/init.md.template` は**ユーザースコープのグローバルコマンド**としてマシンごとに1回だけセットアップする。以後、どの新規プロジェクトでも `/init` と入力するだけで生成処理が走る
- `/init` は `PROJECT_BRIEF.md` の各項目について、次のいずれかに該当するものだけを対話で確認する
  - 空欄(未記入)
  - 記入されているが、AIが内容を読んで曖昧・矛盾・情報不足と判断したもの
  空欄かどうかだけでなく、内容の妥当性もAIが判断したうえで対話に入るかどうかを決める
- ハーネスリポジトリの参照方法は、`init.md` 内にローカルパスを `[要確認: 内容]` 記法で保持する方式(ローカルパス参照)を採用する。既存のPRD「スコープ外」(自動展開CLIは作らず、手動/AIエージェントによるコピー&置換を前提とする)という決定と整合し、実装が最も単純なため

## 影響

- `templates/questions.json` の `usage_note`、`README.md` の「使い方」、`docs/PRD.md`、`docs/ARCHITECTURE.md` は、いずれもこの決定に基づくフロー(ファイル記入 → グローバル`/init` → 空欄/曖昧な項目のみ対話)に統一して記述する
- 新規プロジェクトごとにファイルをコピーする作業は `PROJECT_BRIEF.md` のみで、コマンドファイルのコピーは発生しない
- 将来、この方式でも運用上の手間が大きいと判明した場合は、この決定を見直す新しいADRを起票すること
